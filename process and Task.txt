EF -Core 


Your C# class:

public class Product
{
    public int Id { get; set; }
    public required string Name { get; set; }
    public decimal Price { get; set; }
}

EF Core looks at it and maps:

C#                         Database


Product       ────────→    Products table


Id            ────────→    Id column
Name          ────────→    Name column
Price         ────────→    Price column

Then when you add product data:

Products
┌────┬──────────┬────────┐
│ Id │ Name     │ Price  │  ← EF Core helps create this
├────┼──────────┼────────┤
│ 1  │ iPhone   │ 80000  │  ← data
│ 2  │ Laptop   │ 60000  │  ← data
└────┴──────────┴────────┘

So you don't have to manually create the table and columns with SQL in the normal EF Core workflow. 🎯

One important correction

EF Core doesn't automatically create/update the database just because you wrote the class.

You normally use migrations:

C# Entity
    ↓
EF Core
    ↓
Migration
    ↓
Database

For example:

dotnet ef migrations add InitialCreate

then:

dotnet ef database update

That's what actually tells the database to create/update the tables.

So you've now understood the main reason we're learning EF Core.


🎯 So the big picture
Without EF Core:
C# class
      ↓
You manually write SQL
      ↓
Database table
      ↓
You manually write SQL
      ↓
Data
With EF Core:
C# Entity
      ↓
     EF Core
      ↓
Migration → Database table
      ↓
C# objects / DbContext
      ↓
     EF Core
      ↓
Database

Redux

Suppose your application has a bug:

42 → 43 → 44 → 999 ❌ → 1000

You can go back through the actions and find which action caused the bad state.

That's why Redux DevTools is so useful for debugging complex applications.

And yes, buddy — you can also play through the recorded actions so you can watch 
the state changes happen one after another. 🎬

One small distinction: DevTools is primarily debugging/time-traveling the 
recorded state; it doesn't permanently undo your application's database or backend data.
 It's a development/debugging tool.

React Component

RTK Query
      ↓

Errors
Caching

We used Redux DevTools to inspect:

Action
State
Diff
Trace

This helped us see exactly what happens when an action is dispatched.

❓ Is Redux always necessary?

The instructor explains that Redux isn't mandatory for every React application.

For smaller applications, React's Context API and other approaches can be enough.

Redux becomes useful when an application has more complicated shared state and you want things such as Redux Toolkit, middleware, RTK Query, and DevTools.
